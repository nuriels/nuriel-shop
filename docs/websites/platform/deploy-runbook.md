# Nuriel Websites — פריסה לייצור והאתר של אפרת ב-Preview

> **פריסת המערכת ≠ פרסום האתר.** המסמך הזה פורס את המנוע והתשתיות, מעביר את תוכן האתר של אפרת ובודק את ה-Preview.
> הוא **לא** מפרסם את האתר, לא משנה DNS, לא מחבר דומיין פרטי ולא שולח הזמנה ללקוחה.
> האתר נשאר בטיוטה עם `noindex` ועם `robots.txt` סגור, ולא נחשף לגוגל.
> אחרי סעיף 4 עוצרים ומחכים לאישור לפני פרסום.

**הקומיט לפריסה:** `bd07313`. הוא מופיע גם בדוח. הענף הוא `websites/engine`, והוא כולל את `release/next` שרץ היום בייצור (`773ad14`).

## 1. מה נפרס

|                     |                                                                                                                                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| קוד                 | `websites/engine`, כולל `d89d4fb`, `7101181` ואת הזמנת בעלת האתר + חבילת הפריסה                                                                                            |
| מיגרציות (לפי הסדר) | 193 `bp_engine`, 194 `bp_media`, 195 `bp_site_fonts`, 196 `bp_inquiries`, 197 `bp_site_address`, 198 `bp_owner_invites`. לכל אחת יש Rollback ובדיקת-אחרי                   |
| מתג המנוע           | `BUSINESS_PROFILE_ENGINE=on` ב-‎.env, ודגל הפלטפורמה `business_profile_enabled`. הדגל `business_profile_public` נשאר **כבוי**                                              |
| תוכן                | האתר `efrat` (טיוטה): 90 תמונות ו-10 גופנים בספריית האתר, וטיוטת האתר. 94 קבצים מורדים מהאתר הישן ו-6 מגיעים מ-Git. כולם נבדקים מול SHA-256 של הקבצים שנבדקו בסביבת הבדיקה |

**מה לא נעשה:**

- אין פרסום ואין `live_version`.
- אין שינוי DNS, nginx או דומיין.
- לא נשלחים מיילים.
- אין שינוי בנתוני לקוחות אחרים. הסקריפט משווה checksum של tenants, user_roles, site_settings, orders, billing_history, tenant_subscriptions ו-bookings לפני המיגרציות ואחריהן.

## 2. לפני שמתחילים

- `ADMIN_EMAIL` — האימייל של חשבון מנהל הפלטפורמה שלכם. הסיסמה נשאלת בשלב ה-import ולא מוצגת.
- הרצה מהשרת, בתיקייה `/root/nuriel-shop-git`, כ-root, כמו בפריסות הקודמות.
- כל פקודה עוצרת לבד אם משהו לא תקין. שולחים לי את הפלט של כל פקודה לפני שעוברים לבאה.

## 3. הפקודות, לפי הסדר

**W1 — בדיקה מקדימה (קריאה בלבד, לא משנה כלום)**

```bash
cd /root/nuriel-shop-git && git fetch -q origin +refs/heads/websites/engine:refs/remotes/origin/websites/engine && bash <(git show bd07313:deploy/release-websites.sh) --check bd07313
```

מה נבדק:

- 192 מיגרציות רצות, ו-193–198 עוד לא.
- מקום פנוי בדיסק.
- `docker-compose.yml` מעביר את `BUSINESS_PROFILE_ENGINE`.
- `DNS_TEST_FIXTURES` לא מוגדר.
- האם `RESEND_API_KEY` מוגדר (כן/לא בלבד).
- תיקיית האחסון נמצאת.
- הזמנת בדיקה בחנות הראשית עובדת, בתוך טרנזקציה שמבוטלת (כלום לא נשמר).
- קובצי המיגרציות 193–198 וה-Rollback שלהם קיימים בקומיט.

**W2 — פריסה (כולל גיבוי)**

```bash
cd /root/nuriel-shop-git && bash <(git show bd07313:deploy/release-websites.sh) --deploy bd07313
```

הסדר בתוך הפקודה:

1. **גיבוי** ל-`/root/backups/nuriel-shop/websites-<זמן>/`: `db.dump` (נבדק ב-`pg_restore --list`), `storage.tar.gz` (נבדק ב-`tar -tzf`), image לחזרה `before-websites-<זמן>` וקובץ מצב המתג.
2. קוד ובנייה.
3. מיגרציות 193–198, כל אחת בטרנזקציה עם בדיקת-אחרי.
4. מתג המנוע.
5. הפעלה מחדש ו-Health Check.
6. בדיקות עשן: חנויות קיימות, צימרים, `/platform/websites`, והזמנת בדיקה שמבוטלת.

כישלון אחרי ההפעלה מחזיר את האפליקציה אוטומטית. המסד לא מוחזר אוטומטית, והפקודות לכך מודפסות.

**W3 — פתיחת האתר efrat (טיוטה, בלי בעלים)**

```bash
cd /root/nuriel-shop-git && ADMIN_EMAIL=<האימייל שלכם> bash deploy/websites-efrat.sh open-site
```

- נפתח בשם מנהל הפלטפורמה.
- נרשם ביומן האבטחה, גם ביומן הפלטפורמה וגם ביומן האתר.
- הסקריפט בודק שאין בעלים, שאין גרסה מפורסמת ושהאתר לא ציבורי.
- הרצה חוזרת לא משנה כלום.

**W4 — כלים לסקריפטים (בלי התקנה על השרת)**

```bash
cd /root/nuriel-shop-git && bash deploy/websites-efrat.sh tools
```

`seroval` נלקח מבניית התלויות של האפליקציה עצמה (`docker build --target deps`, מה-cache של הבנייה) ונשמר ב-`.cache/websites-tools`. הסקריפטים רצים ב-`node:22-slim`, ואם הוא לא קיים בשרת — ב-image של האפליקציה (גם הוא Node 22).

**W5 — 100 הקבצים**

```bash
cd /root/nuriel-shop-git && bash deploy/websites-efrat.sh fetch
```

- 94 קבצים מורדים מ-`https://efratadir.com/wp-content/uploads/` בלבד. כללי ההורדה: https בלבד, בלי הפניות, עד 15MB ועד 60 שניות לקובץ, ובדיקת סוג הקובץ לפי התוכן.
- 6 קבצים מגיעים מ-Git.
- אחר כך נבדק SHA-256 של כל 100 הקבצים מול המניפסט. אחרת — עצירה.

**W6 — העלאה לאחסון ושמירת הטיוטה**

קודם הרצת ניסיון, שלא מעלה ולא שומרת כלום:

```bash
cd /root/nuriel-shop-git && ADMIN_EMAIL=<האימייל שלכם> bash deploy/websites-efrat.sh import --dry-run
```

אחר כך ההעלאה עצמה:

```bash
cd /root/nuriel-shop-git && ADMIN_EMAIL=<האימייל שלכם> bash deploy/websites-efrat.sh import
```

**חשבון בלי סיסמה (כניסה בקוד במייל):** מוסיפים `--server-session` לשתי הפקודות.

- החיבור נוצר בשרת באותו מנגנון של כניסת הקוד במייל באפליקציה, עם מפתח השירות מ-‎.env.
- לא נשלח מייל ולא נוצרת סיסמה.
- רק לחשבון שמופיע ברשימת מנהלי הפלטפורמה.
- בסוף מנותק החיבור הזה בלבד; הכניסה בדפדפן לא נפגעת.
- המפתח עובר לקונטיינר דרך משתנה סביבה, לא בשורת הפקודה, ולא מודפס.

- ההעלאה עוברת דרך האפליקציה, כמו העלאה מהעורך: אותן בדיקות סוג וגודל ואותו אחסון.
- הסקריפט מתחבר ל-`127.0.0.1:3700` עם הכתובת `efrat.nuri1.fit`, ולכן לא תלוי ב-DNS או בתעודה.
- `EXPECT_SLUG=efrat` — אם האתר לא `efrat`, נעצר בלי שינוי.
- בסוף נבדק שאין גרסה מפורסמת.

**W7 — בדיקת המדיה והתוכן (קריאה בלבד)**

```bash
cd /root/nuriel-shop-git && bash deploy/websites-efrat.sh audit
```

נבדק:

- 100 קבצים בספרייה, 100 באחסון, וכולם זהים לקבצים שנבדקו.
- כל התמונות נטענות מהכתובת הציבורית של האחסון, וכל 10 הגופנים תקינים.
- ספירות: 9 אזורים, 61 עבודות, 13 המלצות, 5 שירותים, 2 טפסים, וואטסאפ, הצהרת נגישות.
- אין קישורים לאתר הישן, ל-`localhost`, ל-`/tmp` או ל-`file:`.
- האתר לא מפורסם.

התוצאה המלאה נשמרת ב-`.cache/efrat-media-audit.json`.

## 4. בדיקות בדפדפן (אחרי W8)

1. **פאנל הפלטפורמה → אתרי אינטרנט → אפרת אדיר → תיק האתר → "תצוגה מקדימה"**: האתר המלא, כטיוטה.
2. **כניסת מנהל הפלטפורמה לניהול האתר:** כפתור הכניסה בתיק האתר, ואז `efrat.nuri1.fit/studio`, ואז "עריכת האתר". הכניסה נרשמת ביומן.
3. **קישור הזמנה — בדיקה בלי לפתוח חשבון:**
   1. בתיק האתר: "יצירת קישור להזמנת לקוחה". הקישור מוצג פעם אחת, עם "העתקת הקישור".
   2. פותחים את הקישור בחלון גלישה בסתר. צריך להופיע "ברוכה הבאה, האתר שלך מוכן לניהול" עם שם האתר. **לא ממלאים את הטופס** — מילוי פותח את חשבון בעלת האתר.
   3. חוזרים לתיק האתר ולוחצים "ביטול הקישור".
   4. מרעננים את החלון בסתר. הקישור נדחה ("הקישור בוטל"), והניסיון נרשם ביומן.
4. **הקישור האמיתי לאפרת:** יוצרים אותו מאותו כפתור רק כשמחליטים, ושולחים בעצמכם (וואטסאפ). אני לא שולח הזמנה.

## 5. אימות המייל

- **השליחה עוברת דרך Resend** (`RESEND_API_KEY`), אותה תשתית מיילים שכבר עובדת בייצור. אין SMTP בשרת, ו-GoTrue לא שולח מיילים.
- **אחרי פתיחת החשבון:**
  - נשלח קוד בן 6 ספרות.
  - הניהול מציג "כתובת המייל עוד לא אומתה" עד שהקוד מוזן.
  - תיק האתר בפאנל מציג "המייל עוד לא אומת".
- **המייל מסומן כמאומת רק אחרי הזנת הקוד הנכון.** החשבון נפתח ב-`email_confirm` רק כדי שכניסה בסיסמה תעבוד, וזה לא נחשב אימות.
- **אם `RESEND_API_KEY` לא מוגדר** (W1 מציג כן/לא):
  - פתיחת החשבון לא נחסמת.
  - הניהול מציג במפורש ששירות המיילים לא מוגדר.
  - המייל נשאר "לא מאומת" עד שהשירות יוגדר ויישלח קוד.

## 6. חזרה לאחור

**אפליקציה:**

```bash
docker tag nuriel-shop-app-app:before-websites-<זמן> nuriel-shop-app-app:latest
```

ואז ה-checkout של הקומיט הקודם ו-`docker compose up -d`. הפקודה המדויקת מודפסת בסוף W2.

**מתג המנוע:** מחזירים את השורה מ-`engine-switch-before.txt` שבתיקיית הגיבוי.

**מסד:**

- רק באישור.
- מהחדשה לישנה: 198 → 193.
- קובצי ה-Rollback נמצאים בתיקיית הגיבוי, והפקודות מודפסות ב-W2.
- כל Rollback מסרב לרוץ אם כבר יש נתונים בטבלאות החדשות. למשל, אחרי W3, לפני Rollback צריך למחוק את האתר `efrat` מהפאנל.

**שחזור מלא מהגיבוי:**

- `pg_restore` מ-`db.dump`.
- פריסת `storage.tar.gz` לתיקיית האחסון.

## 8. חסמים לפני פרסום (לא לפריסה)

- **אישור של אפרת** לתוכן ולתמונות, כולל רישיון התמונות והאייקונים. ראו `docs/websites/` (מסמך הרישיונות).
- **שירות המיילים:** לוודא ש-`RESEND_API_KEY` מוגדר, כדי שאימות המייל של אפרת ופניות מהאתר יגיעו.
- **התאמות עיצוב פתוחות** מהשוואת הנאמנות: גוונים, ואנימציית העט.
- **כותרת SEO** — מעט ארוכה מהמומלץ; לקצר לפני הפרסום.
- **הפרסום עצמו:** פעולה נפרדת, באישורכם בלבד. היא כוללת את דגל `business_profile_public` לאתר ואת "פרסום" מהניהול. שלב הדומיין הפרטי (אם בכלל) — רק אחרי זה.
