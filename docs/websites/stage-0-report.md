## 5. הארכיטקטורה המומלצת — מנוע `business_profile`

### 5.1 מיקום ובידוד

- **`site_type`:** `'business_profile'` נוסף ל-CHECK של `tenants` ול-`SITE_TYPES` בחוזה. אתר שייך למנוע אחד בדיוק.
- **הקוד:** `src/engines/business-profile/**`.
  - מותר לו לייבא רק את עצמו ואת `src/platform/**`.
  - נוסף כלל גבולות ל-lint, כמו שיש ל-Hospitality.
- **המסד:** סכמה `business_profile`, סגורה ל-anon / authenticated, עם RLS פעיל על כל טבלה.
  - הגישה רק דרך פונקציות `business_profile.*` / `public.bp_*`.
  - כל פונקציה בודקת `current_tenant_id()` ואת תפקיד המשתמש.
- **שער (gate):** אתר `business_profile` מקבל רק את הנתיבים שלו. נתיבי חנות וצימר מחזירים 404, ולהפך.
- **דגלים:**
  - `business_profile_enabled` לפלטפורמה ולאתר — כבוי כברירת מחדל;
  - `business_profile_public` — האתר נראה לציבור רק אחרי פרסום שאושר.

### 5.3 מודל התוכן

- **אתר** (`sites`): תבנית, שפות (`he` / `en` / שתיהן), ערכת צבעים ופונטים, פרטי עסק, הגדרות SEO, ומצב
  (טיוטה / פורסם / מושהה).
- **גרסאות** (`site_versions`): `draft` / `published`, `document` (JSON), ו-`revision` לנעילה אופטימית. זה הדפוס
  שהוכח בצימרים.
  - **פרסום** מעתיק טיוטה לגרסה מפורסמת חדשה.
  - הגרסה הקודמת נשמרת, ולכן אפשר לחזור אחורה.
- **המסמך:** `pages[] → blocks[]`. לכל מקטע: `{id, type, version, props, hidden}`. **טקסטים לפי שפה:** `{he, en}`.
- **רישום מקטעים** (`blocks/registry.ts`). לכל סוג מקטע:
  - סכמת Zod;
  - `normalize` (קלט ישן → גרסה נוכחית);
  - רכיב תצוגה לכל תבנית;
  - טופס עריכה;
  - ברירת מחדל.

  סוג מקטע חדש = קובץ חדש, בלי מיגרציה. ב-v1: Hero, About, Services, Portfolio, Testimonials, Gallery, Text,
  CTA, Contact, FAQ, Stats, Logos, Video, Map, Footer.

- **אוספים** (טבלאות): שירותים, המלצות, פריטי תיק עבודות.
  - מקטע "שירותים" מציג את האוסף.
  - ממשק הניהול מנהל אותם כרשימות.
  - העוזר יכול לענות מהם, אם הבעלים אישר.
- **תבניות:** Elegant, Professional, Creative, Minimal, Luxury, Portfolio. כל תבנית היא:
  - ערכת טוקנים — טיפוגרפיה, צבעים, מרווחים, פינות, תנועה;
  - גרסה לכל רכיב מקטע;
  - פונטים מקומיים (בלי Google Fonts בזמן ריצה);
  - RTL מלא, ו-LTR לאנגלית.
- **פרסום:** הבעלים מסמן "מוכן לפרסום". **הפרסום הראשון של אתר דורש אישור של מנהל הפלטפורמה** (כמו "אין לפרסם
  אתר של לקוח ללא אישור מפורש"). המשך — לפי שאלה 3.

### 5.4 העורך

- **תצוגה מקדימה:** iframe של הטיוטה עם מתג מחשב / נייד; עריכה במקום (inline) לטקסטים — כמו בעורך הצימרים.
- **מקטעים:** הוספה מרשימת סוגים, גרירה לסידור, הסתרה ומחיקה.
- **אוספים:** מסכי רשימה נפרדים (שירותים, המלצות, תיק עבודות) עם תמונות מספריית המדיה.
- **עיצוב:** בחירת תבנית, צבעים (עם בדיקת ניגודיות AA), פונטים מרשימה סגורה, רקעים.
- **קשר:** טלפון, WhatsApp, אימייל, כתובת, רשתות חברתיות. כפתורי WhatsApp וטלפון צפים, לפי בחירה.

## 8. Website Importer — תכנון

**התהליך:**

1. **כתובת:** בעל העסק או מנהל מזין כתובת.
2. **סריקה:**
   - רק אותו דומיין, ועד 50 עמודים / עומק 3;
   - בקשה אחת לשנייה;
   - לפי `robots.txt` ו-sitemap;
   - רק GET ציבורי — בלי טפסים, בלי התחברות, בלי עקיפת CAPTCHA.
3. **חילוץ:**
   - כותרות וטקסט נקי;
   - תמונות (src, alt, מידות);
   - Meta ו-OG;
   - JSON-LD;
   - טלפונים, אימיילים, WhatsApp ורשתות חברתיות;
   - תפריט הניווט.
4. **סיווג:** שירותים, המלצות, פרויקטים, אודות, קשר — היוריסטיקות לפי מבנה וכותרות. בעתיד אפשר להוסיף AI
   כאפשרות, עם אישור.
5. **תצוגה מקדימה:**
   - מה נמצא בכל עמוד;
   - בחירה מה לייבא;
   - מיפוי לתבנית;
   - מיפוי כתובות ישנות → חדשות.
6. **ייבוא:** ל**טיוטה חדשה** בלבד.
   - התמונות מורדות, נבדקות ומומרות ל-WebP / AVIF בספריית המדיה.
   - הכתובות הישנות נכנסות ל-`redirects`.
   - **אין פרסום אוטומטי ואין דריסה.**

**אבטחה — חובה:**

- **SSRF:** משתמשים ב-`assertFetchableUrl` / `safeLookup` / `isBlockedAddress` הקיימים.
  - חסומים: IP פנימי, loopback, link-local (169.254.x כולל metadata של ענן), IPv6 פנימי, 0.0.0.0.
  - הבדיקה רצה **בכל הפניה** ועל כתובת ה-IP שנפתרה (נגד DNS rebinding).
  - רק פורטים 80 ו-443.
- **הפניות:** עד 6. מעבר לדומיין אחר מסומן ולא נסרק.
- **גודל וזמן:** עמוד עד 6MB / 15 שניות. תמונה עד 10MB. סוג הקובץ מזוהה מהבייטים (לא מה-header). SVG לא
  מיובא (או רק אחרי ניקוי).
- **XSS:** טקסט בלבד, או HTML מוגבל שעובר ניקוי לפי רשימה סגורה. אין `<script>`, אין `on*=`, ואין
  `javascript:`. הרינדור באתר הוא כטקסט / רכיבים.
- **הרשאות:** רק בעל העסק של האתר או מנהל-על. הייבוא רץ בשרת עם אתר הבקשה, ומגבלת קצב לאתר ולמשתמש.

## 9. ייבוא מגיבוי — תכנון

**פורמטים:**

- **WordPress WXR (XML):** עמודים, פוסטים, קבצי מדיה, קטגוריות.
- **ZIP של מדיה.**
- **CSV / JSON:** שירותים, המלצות, פרויקטים — לפי תבנית קובץ שנפרסם.
- **HTML סטטי** (ZIP).
- **ייצוא Wix / Squarespace:** בהמשך, לפי מה שאפשר.

**התהליך:**

1. העלאה לדלי **פרטי** `bp-imports` (הסגר).
2. בדיקת תקינות וסריקת אבטחה.
3. זיהוי התוכן.
4. תצוגה מקדימה.
5. מיפוי לתבנית.
6. אישור.
7. ייבוא כטיוטה חדשה.

**הגנות:**

- **ZIP bomb:** תקרת יחס דחיסה, מספר קבצים, גודל כולל אחרי פריסה ועומק תיקיות.
- **Path traversal:** דחיית `..`, נתיבים מוחלטים ו-symlinks. הפריסה תמיד לשמות שאנחנו קובעים.
- **XML:** בלי DTD / ישויות חיצוניות (XXE), ומגבלת גודל.
- **קבצים:** רשימת סוגים סגורה, זיהוי מהבייטים, קידוד מחדש של תמונות ב-sharp (מסיר EXIF וקוד מוטמע). קבצי
  הרצה ו-HTML עם סקריפטים — נדחים.
- **דריסה:** אף פעם לא נדרס אתר או אוסף קיים. תמיד טיוטה חדשה, ומחיקה רק באישור מפורש.

## 11. דומיינים — תכנון

- **דומיין Nuriel:** `<slug>.nuri1.fit`, כמו היום. בחירת `slug` פנוי בפתיחה (דוגמה: `efrat`).
- **דומיין אישי:**
  1. הזנה. נבדקים פורמט, שהדומיין לא תפוס אצל לקוח אחר, ושאינו של Nuriel.
  2. **הוראות DNS:** `A` / `CNAME` לשרת, ו-`TXT _nuriel-verify.<domain> = <token>` לאימות בעלות.
  3. **בדיקה:** פתרון DNS בשרת, קריאה בלבד.
  4. **מאומת** ← סוכן ה-SSL הקיים מנפיק תעודה ← **SSL פעיל**.
- **קנוני:**
  - בחירה בין `www` / בלי `www` / דומיין Nuriel.
  - שאר הכתובות מפנות ב-301 לקנונית.
  - ה-Sitemap ו-`canonical` לפי הבחירה.
- **ניתוק / החלפה:** הדומיין הקודם מסומן כמנותק, והאתר חוזר ל-`<slug>.nuri1.fit`.
- **אנחנו לא משנים DNS ולא רוכשים דומיינים.** ההוראות לבעל הדומיין בלבד.

## 12. עוזר AI לגולשים — תכנון

- **הגדרות לכל אתר:** פעיל, שם, פתיח, שפה, סגנון, מגבלות (שאלות ביום / לגולש), ונתוני שימוש.
- **ידע:** רק `assistant_knowledge`. אלה קטעים שהבעלים **אישר** מתוך תוכן האתר — שירותים, אודות, שאלות נפוצות,
  שעות ואזורי שירות. **אין גישה לשום דבר אחר.**
- **ריצה:**
  - פונקציית שרת אחת. הפרומפט נבנה בשרת מהידע של **האתר של הבקשה בלבד**.
  - **בלי כלים** — אין קריאה למסד, לשרת או לאתר.
  - אם אין תשובה בידע — הפניה ליצירת קשר.
- **ספק:** דרך ה-router הקיים של NURIEL AI (מפתח מוצפן בשרת, מכסות, תקרת תקציב). **בשלב הפיתוח — ספק מדומה
  בלבד, בלי מפתח ובלי חיוב.**
- **אבטחה:**
  - הגנה מ-prompt injection: הוראות קבועות + ידע מסומן כנתונים.
  - מגבלת קצב לפי IP ולפי אתר.
  - אין שמירת פרטים אישיים מעבר לנדרש.
  - יומן שימוש ב-`audit_log` (בלי תוכן השיחה, או עם תוכן מקוצר — שאלה 10).
- **בידוד:** בדיקת מסד ובדיקת E2E — עוזר של אתר A לא מקבל לעולם ידע של אתר B.
