# Nuriel Websites — דוח Stage 2: עורך, תבניות, ספריית מדיה, ותצוגה מקדימה של אתר אפרת אדיר

ענף: `websites/engine` · בלי Merge, בלי פריסה, בלי מיגרציות בייצור, בלי DNS, בלי פרסום, בלי חיובים.

## 1. בקצרה

- **בעל העסק עורך את האתר בעצמו.** בצד אחד כל התוכן, בצד השני תצוגה מקדימה חיה במחשב (1280px, מוקטנת למסך) או
  בנייד (390px). השינוי מופיע בתצוגה **מיד, לפני השמירה**. השמירה נכנסת לטיוטה בלבד, והגולשים רואים אותה רק אחרי פרסום.
- **ספריית מדיה מאובטחת.** כל תמונה נבדקת, מקודדת מחדש בשרת (WebP בשלושה גדלים ו-AVIF) בלי מטא-דאטה ובלי מיקום,
  ונשמרת בתיקייה של האתר בלבד. יש מכסה לכל אתר.
- **שתי תבניות:** Elegant ו-Portfolio (החלטה 4). ארבע התבניות הנוספות רשומות כ"בקרוב". הוספה של תבנית היא רשומה
  וקוד תצוגה, בלי שינוי במנוע.
- **מנהל הפלטפורמה רואה בבדיקת הפרסום הראשון בדיוק את הצילום שנשלח, עם התמונות שלו.** לא את הטיוטה ולא את כל הספרייה.
- **האתר של אפרת אדיר בנוי כטיוטה** מהתוכן של האתר הציבורי שלה, בלי תמונות ובלי תוכן מומצא. **הוא לא פורסם**, ולא
  בוצע שום שינוי DNS. תצוגה במחשב ובנייד: §7.

## 3. השרת — העלאת תמונות (`data/media.server.ts`, `api/media.functions.ts`)

1. **בדיקת סוג הקובץ מהבייטים**, לא מהשם ולא מה-MIME שהדפדפן שלח:
   - SVG, HEIC, HTML ו"תמונה" שאינה תמונה נדחים;
   - עד 12MB ועד 50 מגה-פיקסל;
   - בלי אנימציה.
2. **קידוד מחדש עם sharp:**
   - WebP: ‏1600 / 960 / 480;
   - AVIF: ‏1600;
   - **בלי EXIF ובלי מיקום.** נבדק ב-E2E: קובץ עם EXIF נשמר בלעדיו.
3. **סדר הבדיקות:** מכסה והרשאה **לפני** שמירת קבצים. השמירה בדלי עם הטוקן של המשתמש, ומדיניות ה-Storage בודקת
   שוב את התיקייה. אם הרישום במסד נכשל, הקבצים נמחקים.
4. **מגבלת קצב:** 120 העלאות ב-10 דקות למשתמש.
5. **באתר:** `srcset` (‏480 / 960 / 1600), ו-`<picture>` עם AVIF לדפדפנים שתומכים.

## 4. העורך (`/studio/editor`)

| לשונית                        | מה                                                                                                                                 |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| מקטעים                        | סדר, הסתרה, מחיקה, הוספה (פתיח אחד לעמוד), ועריכת כל מקטע: פתיח, אודות, שירותים, תיק עבודות, המלצות, קריאה לפעולה, יצירת קשר, טקסט |
| פרטי העסק                     | שם, משפט, לוגו, WhatsApp והודעה מוכנה, טלפון, אימייל, כתובת, שעות, רשתות (רק `https://`)                                           |
| עיצוב                         | תבנית, 7 צבעים, פינות. **בדיקת ניגודיות AA בזמן העריכה**: כל זוג חלש מוצג בשמו וביחס שלו                                           |
| שירותים / תיק עבודות / המלצות | רשימות עם סדר, הסתרה ומחיקה; קטגוריות לתיק העבודות; תמונה לכל פריט                                                                 |
| תמונות                        | הספרייה: העלאה, טקסט חלופי (לקוראי מסך ולגוגל), מחיקה, ניצול המכסה                                                                 |

- **התצוגה המקדימה:**
  - מתעדכנת מהודעה של העורך (`postMessage`), רק מאותו מקור ורק מחלון האב;
  - המסמך עובר נרמול לפני ההצגה, ותמונות מתקבלות רק מכתובת http/https או מנתיב באתר;
  - המסגרת מודיעה כשהיא מוכנה, וגם אחרי רענון היא מקבלת את המסמך העדכני.
- **שמירה:**
  - עם `revision`: אם מישהו אחר שמר בינתיים, לא דורסים. מוצג הסבר וכפתור לטעינה מחדש;
  - Ctrl+S שומר;
  - אזהרה ביציאה עם שינויים שלא נשמרו.
- **בתבנית אחרת:** בחירת תבנית מחליפה גם את ערכת הצבעים להתחלה של התבנית. כל הצבעים שבה עוברים AA (נבדק ביחידה).
- **הרשאות:** בעל העסק ומנהל הפלטפורמה רשאים להכול. מנהל רגיל עורך תוכן ותמונות, בלי פרסום ובלי שחזור (כמו ב-Stage 1).

## 9. הערות לשלב הבא

- **המטמון של 15 השניות** בדגלים ובמצב האתר נשאר כמו ב-Stage 1.
- **הטיוטה של אפרת קיימת רק בבדיקה.** היא נוצרת ונמחקת בכל ריצה. פתיחת האתר שלה בפלטפורמה (`efrat.nuri1.fit`)
  תיעשה ב-Stage 6, מהפאנל, וגם אז כטיוטה, עד אישור.
- **מחיקת תמונות מהדלי** נעשית בשרת עם הטוקן של המשתמש. במחיקת אתר שלם, ניקוי התיקייה בדלי יתווסף לתהליך מחיקת
  האתר (Stage 4, יחד עם הדומיינים).
