> `claude/ecstatic-euler-z7wmrg` (= הקוד שבייצור `eccd001` + עבודת ה-SEO מ-17.11).

## 3. מה מוסיפים (מינימום)

1. **מדריכי SEO בקטלוג של Hospitality** (4–5 מדריכים: שיפור בגוגל, כותרות ותיאורים, תיאורי תמונות, מה חסר, קידום
   מקומי). הנתב הקיים כבר יודע לבחור אותם — אין קריאה נוספת להבנת כוונה. `catalogId` נשאר `hospitality-v1`.
2. **כפתור פעולה במדריך** ב-`AssistantWidget` (שדה אופציונלי `action` במדריך): "להכנת הצעות" → מסך ההצעות. **החלון
   עצמו ממשיך לא להציג טקסט של הדגם** — ההצעות מוצגות רק במסך הבדיקה, אחרי ולידציה.
3. **`hospitality/ai/seo-writer.server.ts`** — בתבנית של "מוצרים כפולים": הקשר מוגבל של העסק הנוכחי בלבד (שם, יישוב,
   תיאור המתחם, "מידע שימושי", יחידות: שם, קיבולת, חדרים, תיאור, מתקנים; שדות SEO נוכחיים; הביטויים של העסק;
   לתיאורי תמונות — התמונה בגודל 480px בלבד). פלט ב-JSON schema סגור. השרת בודק כל ערך (אורך, טקסט בלבד, בלי < >,
   בלי קישורים / טלפונים / אימיילים שלא קיימים בנתוני העסק) ומוסיף אזהרות דחיסה.
4. **מקום להצעות עד לאישור** — טבלה אחת `hospitality.seo_proposals` (**מיגרציה אחת**; tenant + RLS כמו כל טבלה של
   Hospitality; כתיבה רק דרך פונקציות): יעד (עמוד / יחידה / תמונה), שדה, הטקסט המוצע, **הערך שהיה בזמן ההפקה**,
   מקור (`template` / `ai`), מצב (ממתין / אושר / נדחה / הוחלף), מי ומתי.
   - **אין דריסה:** אישור עובר רק אם הערך הנוכחי עדיין שווה לערך שהיה בזמן ההפקה — אחרת "השתנה מאז, לא הוחלף".
     ההפקה האוטומטית מציעה רק לשדות ריקים / בברירת מחדל — אף פעם לא לשדה שהלקוח כתב.
   - חלופה בלי מיגרציה (לשמור בתוך טיוטת האתר) — **לא מומלצת**: מתנגשת עם השמירה האוטומטית של העורך (revision), ושדות
     יחידה ותמונה בכלל לא נמצאים במסמך האתר.
5. **מסך "הצעות לשיפור בגוגל"** בלשונית "גוגל ושיתוף": לפי עמוד — לפני / אחרי, עריכה, אישור בודד, אישור של כמה,
   ביטול, "ניסוח אחר" (קריאה אחת, נספרת במכסה). הסבר פשוט, בלי מונחים.
6. **מחולל תבניות בלי AI** (`seo-templates.ts`, טהור): כותרות ותיאורים מנתונים מאומתים (שם, יישוב, סוג, קיבולת,
   חדרים). חינם, לכל לקוח.
7. **הפעלה ראשונית:** כשהבעלים פותח לראשונה את "גוגל ושיתוף" / את הצעד במדריך, ויש שם עסק ולפחות יחידה אחת — פעם
   אחת לעסק (מנעול במסד). **מה בדיוק רץ — לפי ההחלטה בסעיף 4.**

**לא נוגעים:** ספק, מפתח, בחירת דגם, טבלאות החיוב / החבילות / המכסות, מסך מנהל העל, Ecommerce, Websites.

## 4. ההפקה הראשונית האוטומטית — החלופות (החלטה שלך)

עלות משוערת להפקה מלאה לעסק כמו נופי דורית (5 יחידות + 73 תמונות ב-480px), לפי המחירים בקוד:
**Haiku ≈ 0.01$**, Sonnet ≈ 0.25$, Opus ≈ 0.50$ (כ-75 אלף טוקני קלט ו-10 אלף פלט). נספר בתקרת התקציב החודשית
**המשותפת לכל הפלטפורמה**.

| חלופה                                                              | AI אוטומטי                                | עלות לפלטפורמה     | שינוי במודל החיוב |
| ------------------------------------------------------------------ | ----------------------------------------- | ------------------ | ----------------- |
| **א. תבניות לכולם, AI רק לפי בקשה**                                | אין                                       | 0                  | לא                |
| **ב. א' + הפקת AI אוטומטית אחת ללקוחות עם NURIEL AI פעיל** (מומלץ) | פעם אחת לעסק, בתוך המכסות והתקציב הקיימים | סנטים לעסק         | לא                |
| ג. הפקת AI "ברוכים הבאים" לכל עסק חדש, גם בלי חבילה                | לכולם                                     | על חשבון הפלטפורמה | **כן**            |
| ד. ידני בלבד (כפתור)                                               | אין                                       | 0                  | לא                |

- **ב'** — ללקוח בלי חבילה: מקבל את התבניות החינמיות, ומשפט "שיפור הניסוח ותיאורי התמונות זמינים בשירות NURIEL AI"
  (בדיוק כמו ההודעות הקיימות של העוזר). אין קריאה לדגם ואין חיוב.
- **ג'** משנה את מודל החיוב וגם מסכן לקוחות משלמים: התקרה החודשית משותפת, כך שהפקות חינם יכולות לנצל אותה. אם
  תרצה — צריך תקרה נפרדת. **לא אבצע בלי החלטה שלך.**

## 5. אבטחה והרשאות של היכולת

- tenant **רק מהכתובת** ומהטוקן (`resolveCaller`), אף פעם מהדפדפן; תפקיד בעלים / מנהל; זכאות בכל קריאה.
- לדגם אין כלים, אין רשת, אין מסד ואין מפתחות; הוא מקבל רק את ההקשר שהשרת בנה לעסק הנוכחי. טקסט העסק עטוף בתגיות
  ומוגדר כנתונים, לא כהוראות.
- **אין פרסום אוטומטי:** ההצעות נשמרות כ"ממתינות". אישור = שמירה דרך הפונקציה הקיימת של אותו שדה (טיוטת האתר עדיין
  דורשת "פרסום"). כל אישור — ביומן הפעולות של העסק.
- אין גישה לשרת, לסודות או ללקוחות אחרים — הכול דרך פונקציות שרת מוגדרות עם בדיקת tenant במסד (RLS + `_manage_tenant`).

## 6. היקף

- **עכשיו: Hospitality** — לכל עסק אירוח חדש, לא רק נופי דורית. החבילה `nuriel_ai_hospitality` היא שקובעת זכאות.
- **Ecommerce / Websites — בשלב הבא (החלטה שלך):** לחנויות יש כבר שדות SEO למוצרים ולחנות; ל-Websites אין חבילת AI
  בכלל. המבנה של ההצעות כללי מספיק כדי להוסיף אותם בלי לשנות את הליבה.

## 7. בדיקות שיורצו אחרי המימוש

Typecheck · Lint · יחידה (כולל "דגם עוין" מזויף: פלט ארוך / HTML / קישורים / עסק אחר) · SQL + RLS (בידוד בין עסקים,
