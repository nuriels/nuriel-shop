# שליחת רישיון דיגיטלי ללקוח — מודול פיילוט (נוריאל מחשבים)

ענף: `hospitality/stage-2`. **לא בוצע מיזוג ל-main, לא פריסה, ולא אף שינוי בשרת / במסד הייצור.**
מיגרציה חדשה אחת (54) עם Rollback. נבדק מקומית: יחידה, מסד (3 סבבים), Rollback, מקביליות, E2E.

---

## 1. מה זה ואיפה

- **איפה:** פאנל הניהול של החנות ← "התראות מייל" ← הכרטיס **"שליחת רישיון דיגיטלי ללקוח"** (ראשון בעמוד).
  שלוש לשוניות: **שליחה**, **היסטוריה**, **קבצי ברירת מחדל**. עברית מלאה, RTL, מחשב ונייד.
- **למי:** רק לחנות שהפיילוט הופעל לה (דגל `digital_licenses` — פעיל בפלטפורמה **וגם** לחנות), ורק לבעל
  החנות / מנהל. בכל חנות אחרת, ולקופאי / מחסנאי / סוכן / לקוח — הכרטיס לא מוצג, וכל פעולה בשרת נחסמת.
- **החנות נקבעת בשרת** לפי הכתובת (host) ← המסד. אף מזהה חנות לא מגיע מהדפדפן.

### הזרימה

1. בוחרים **Office** / **Windows**, ממלאים פרטי לקוח (שם, אימייל, טלפון; ח.פ. ומספר הזמנה — לא חובה)
   ואת מפתח הרישיון (מוסתר כברירת מחדל; מסודר אוטומטית ל-5 קבוצות של 5).
   מתחת לשדה — הנוסח המדויק: "הרישיון אינו אישי ומיועד להתקנה אחת בלבד. המערכת מזהה התקנות כפולות באופן אוטומטי."
2. **קבצים:** מדריך ההתקנה (PDF) — מצורף למייל; תוכנת ההתקנה (EXE) — **לא מצורפת**: נשמרת באחסון פרטי והלקוח
   מקבל קישור הורדה אישי; קבלה (PDF) — לא חובה, מצורפת. ברירת המחדל נבחרת לבד לכל מוצר, ואפשר להחליף.
3. **תצוגה מקדימה מלאה** לפני שליחה: הנמען, המוצר, המפתח (מוסתר, אפשר להציג), הקבצים, הקישור, והמייל עצמו
   בדיוק כפי שייבנה — ברוחב מחשב ונייד. שום דבר לא נשלח לפני הלחיצה על **"שליחת הרישיון ללקוח"**.
4. **סטטוס אמיתי:** "התקבל לשליחה" (הספק קיבל) → "נמסר" **רק** אחרי אישור מסירה מהספק (נבדק אוטומטית אחרי
   השליחה, ובכפתור "בדיקת סטטוס מסירה"); "נכשל" (נדחה / bounce); "לא ידוע" (תקלת תקשורת — ייתכן שיצא).
5. **היסטוריה:** שם, אימייל, טלפון, מוצר, הזמנה, תאריך, סטטוס מייל, מצב קישור, הורדות. בלי מפתחות מלאים.
   בחלון הפרטים: הצגת המפתח המלא (נרשמת ביומן: מי ומתי; מוסתר שוב אחרי 30 שניות), קישור חדש (מוצג פעם אחת
   להעתקה, אפשר גם לשלוח ללקוח במייל), שליחה חוזרת, ביטול קישור, ויומן הפעולות.

### קישור ההורדה

- הכתובת: `https://<החנות>/license-download#<Token>`. ה-Token (256 ביט אקראיים) **אחרי `#`** — הדפדפן לא שולח
  אותו לשרת בפתיחת העמוד: לא ביומני השרת / Nginx, וסורקי קישורים במיילים (Outlook / Gmail) לא "מנצלים" הורדות.
  העמוד מסיר אותו משורת הכתובת, וההורדה עצמה — POST בלחיצה.
- במסד נשמר **רק ה-SHA-256** של ה-Token. אין נתיב פנימי ואין כתובת קבועה לקובץ.
- **7 ימים ועד 3 הורדות** — נאכף במסד, בעדכון אטומי אחד (גם בלחיצות מקבילות: בדיוק 3 עוברות).
  הורדה נספרת רק כשהקובץ באמת יוצא מהאחסון.
- קישור חדש מבטל את הקודם. **החלפת קובץ לא שוברת קישורים שכבר נשלחו:** כל קישור צמוד לקובץ שנשלח איתו,
  גם אחרי העלאת גרסה חדשה או הסרת הישנה מהרשימה.
- הגבלת קצב לפי IP (בדיקה 60 / הורדה 20 ל-10 דקות). כל ניסיון הורדה שנחסם (פג / נוצל / בוטל) נרשם ביומן.

## 2. אבטחה ופרטיות

| נושא          | מה נעשה                                                                                                                                                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| מפתחות רישיון | מוצפנים לפני המסד: AES-256-GCM, מפתח נגזר (HKDF) מ-`LICENSE_KEYS_SECRET` שבסביבת השרת בלבד; AAD = החנות + השליחה (צופן שהועתק לשורה / לחנות אחרת לא מפוענח). במסד: הצופן, 5 התווים האחרונים, וטביעת HMAC לזיהוי "המפתח כבר נשלח". |
| לוגים         | שום מפתח / Token / צופן לא נכתב ללוג. מייל הרישיון **לא** נשמר ביומן המיילים של הלקוח (customer_emails), כי יש בו מפתח. הודעות שגיאה עוברות מיסוך של המפתח. נבדק ב-E2E (שורות המסד) ובלוג השרת של ההרצה.                          |
| הרשאות        | כל פעולת שרת בודקת מחדש: חנות לפי host ← דגל הפיילוט ← בעל חנות / מנהל. הטבלאות — RLS בלי מדיניות, אין הרשאות ל-anon / authenticated, רק service_role.                                                                            |
| בין חנויות    | כל שאילתה מסוננת לפי החנות; מפתחות זרים מורכבים (חנות + מזהה); טריגר שמוודא שקובץ / קישור שייכים לאותה חנות ולאותו מוצר; Token של חנות אחת "לא נמצא" בחנות אחרת.                                                                  |
| קבצים         | Bucket פרטי `license-files` (עד 50MB, PDF / EXE בלבד). העלאה בקישור חתום לנתיב שהשרת בחר בתיקיית החנות; אחרי ההעלאה השרת בודק את **הקובץ האמיתי** (חתימת PDF / כותרת PE של EXE) וגודל — קובץ לא תקין נמחק ונרשם.                  |
| שליחה כפולה   | מפתח idempotency ייחודי במסד לכל שליחה (לחיצה כפולה / ניסיון חוזר = אותה שליחה, מייל אחד); מפתח שכבר נשלח ללקוח אחר — דורש אישור מפורש.                                                                                           |
| יומן          | `license_audit` — הוספה בלבד (עדכון / מחיקה נחסמים בטריגר): שליחה, שליחה חוזרת, צפייה במפתח המלא, קישור נוצר / בוטל, הורדה, הורדה שנחסמה, קבצים, שינויי סטטוס.                                                                    |

## 4. פריסה (כשתאושר)

**המדריך המלא, עם הפקודות המדויקות לשרת ובסדר הביצוע:** `docs/licenses/deploy-runbook.md` — בדיקות מקדימות,
גיבוי ובדיקת שחזור, שחרור האבטחה (45–53), הסוד ומיגרציה 54, הפעלת הפיילוט, בדיקות אחרי פריסה ו-Rollback.
כל פקודות ה-SQL וה-git שבו הורצו מראש על עותק מקומי במצב של השרת.

העקרונות:

- **הסדר:** 45–53 ← 54 ← הגרסה החדשה. 54 לא תלויה ב-45–53 במסד, אבל הקוד של `7ec7a26` צריך את כל העשר.
  הבנייה — לפני המיגרציות (האתר ממשיך לרוץ), והמיגרציות וההפעלה — ברצף קצר.
- **`LICENSE_KEYS_SECRET`:** נוצר פעם אחת בשרת (`openssl rand -hex 32`), נשמר ב-`.env` ובעותק מוצפן מחוץ לשרת,
  ו**לא מוחלף**. לא מריצים `setup-selfhost.sh` כדי ליצור אותו: הסקריפט כותב את `.env` מחדש ומוחק משתנים שהוא
  לא מכיר.
- **הפיילוט:** רק אחרי זיהוי החנות של `nuriel-shop.nuri1.fit` ואישור שזו נוריאל מחשבים. הפקודה מסרבת אם ה-id
  לא תואם לכתובת, או אם חנות אחרת כבר מופעלת.

**כיבוי מהיר (בלי rollback):** `UPDATE public.tenant_feature_flags SET enabled = false WHERE key = 'digital_licenses';`
— הכרטיס נעלם והקישורים מפסיקים לעבוד (עד 15 שניות). הנתונים והסוד נשמרים.

**Rollback של מיגרציה 54 עצמה** (`supabase/rollbacks/20261107100000_lic_digital_licenses.down.sql`) **מוחק** את
היסטוריית השליחות, הקישורים והיומן — לא חלק מתוכנית החזרה. החזרה לגרסה הקודמת (R2 במדריך) משאירה את 54.

## 6. סיכונים ודברים פתוחים

- **`LICENSE_KEYS_SECRET`:** אם יאבד — אי אפשר להציג / לשלוח שוב מפתחות שנשמרו (המיילים שכבר נשלחו לא נפגעים).
  חובה בגיבוי הסודות. אין מנגנון סבב (הפורמט מסומן `v1:` לסבב עתידי).
- **תוכנת ההתקנה לא חתומה (Authenticode):** Windows SmartScreen ואנטי-וירוסים עלולים להזהיר את הלקוח. מומלץ לחתום.
- **מדריך ה-PDF** מזכיר את השם הישן `NurielOfficeTool.exe` — לעדכן ל-`NurielOfficeInstaller.exe`.
- **גודל:** עד 50MB לתוכנה (מגבלת ברירת המחדל של שירות האחסון). התוכנה הנוכחית ~7.5MB.
- **המודול הקיים `sendDigitalLicense` (ממסך ההזמנות)** — לא שונה: המפתח נשמר שם בטקסט גלוי
  (`order_items.digital_license_key`), והמייל עם המפתח נשמר ביומן המיילים של הלקוח. מומלץ להעביר אותו למנגנון החדש.
- **"נמסר"** תלוי באירועי הספק (Resend): אם הספק לא מדווח מסירה — הסטטוס נשאר "התקבל לשליחה" (בכוונה, לא "נמסר").
- **מייל נשלח עם המפתח בגוף ההודעה** (כך נדרש) — מי שיש לו גישה לתיבת הלקוח רואה אותו.
