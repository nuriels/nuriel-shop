# תיקון ממצאי ביקורת האבטחה (2026-11-03) — דוח מסכם

ענף: `hospitality/stage-2`. **לא בוצע מיזוג ל-main, לא פריסה, ולא אף שינוי בשרת / במסד הייצור / ב-Nginx / ב-Kong.**
כל התיקונים בקוד, במיגרציות חדשות (כל אחת עם Rollback) ובסקריפטים — והכול נבדק מקומית.

סימון הסיווג:
- ✅ **תוקן** — בקוד / במיגרציה, עם בדיקות.
- 🟡 **תוקן חלקית** — החלק שבקוד תוקן; היתר מסווג באחת הקטגוריות הבאות.
- 🖥 **דורש שינוי תשתית / שרת** — פעולה בשרת (לא בוצעה, לפי ההנחיות).
- ⚖ **דורש החלטה עסקית / משפטית**.
- ➖ **לא רלוונטי / סיכון שנשאר מתועד** — אחרי בדיקה.

## 3. סדר פריסה מומלץ (כשתאושר פריסה)

1. גיבוי מלא (§1 במדריך ההתקנה), ורצוי עותק קר.
2. **בחלון קצר אחד:** מיגרציות 45 → 53 לפי הסדר, ומיד אחריהן האפליקציה החדשה (`bun install --frozen-lockfile` — sharp 0.35.5).
   - 48 מחליפה את החתימה של `marketing_set_consent`, ו-52 מקבלת קוד קופון רק מהשרת — אפליקציה ישנה מול מסד חדש
     (או להפך) תיכשל בהסכמה לדיוור / בקוד קופון באתר אירוח עד שהשניים מתיישרים.
3. `setup-selfhost.sh --env-only` — יוצר `LOGIN_CODE_SECRET` (L13).
4. `bash deploy/check-default-secrets.sh` — ולהחליף סודות בברירת מחדל (M4).
5. גיבוי מוצפן ל-nuriel-shop: מפתח age במחשב אישי → `backup-install.sh` → תרגיל שחזור (H6).
6. Nginx/Kong: Studio מחוץ לדומיין ה-API, `nosniff`/CSP ל-`/storage`, `server_tokens off` (H4, M1).
7. לבדוק שחסימת `POST /auth/v1/signup` (פעולת הביניים) עדיין פעילה.

## 4. מה נשאר / סיכונים

- **שרת (לא בוצע):** סעיפים 3–7 למעלה; L10 (PKCE), L14, L15, L16 (התשתית), PRV-10/16.
- **החלטות:** L1, L7, L8, L12, PRV-5, PRV-6 (לוגים), PRV-8 (הסרה), PRV-9 (מפתח), PRV-11–15, PRV-18, M5 (תקופות), H5 (מנויים ותיקים), H6 (גיבויים ישנים).
- **H1 — חשבונות קיימים:** הגיבוי-קדימה מסמן כחשבון מאומת כל חשבון קיים עם תפקיד או בלי סיסמה (בייצור אומת: 0 הרשמות עצמאיות). חשבון שנרשם בטופס לפני הפריסה — מאומת לפי הכלל הזה.
- **H1 — חשבון שנרשם בטופס ונעשה מאומת בכניסה בקוד:** אם תוקף רשם מראש את המייל של מישהו (וקבע סיסמה), והקורבן נכנס אחר כך בקוד לאותו חשבון — לתוקף עדיין יש את הסיסמה (pre-hijacking קלאסי). סגירה מלאה = אימות מייל בטופס ההרשמה (החלטת מוצר).
- **GoTrue:** נבדק מקומית (v2.197) ששינוי אימייל דורש אישור גם עם אוטו-אישור — לבדוק את הגרסה בייצור.
- **L3:** אורקל תפקיד לפי uuid (מתועד למעלה).

שנמסר בשיחה (בדיקות יחידה, מסד, rollback, E2E).
