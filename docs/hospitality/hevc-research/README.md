# מחקר: המרת סרטוני HEVC מהאייפון ל-MP4 H.264 (סרטון הפתיח)

> **מחקר בלבד.** האפליקציה לא משתמשת בקבצים כאן, ושום דבר לא הותקן בשרת. הם נשמרים כבסיס אם יוחלט
> לפתח את ההמרה (משימה נפרדת, באישור).

- `REPORT.md` — הדוח המלא (באנגלית): מדידות של עלויות (מעבד, זיכרון, גודל), אבטחה (חסימת רשת וקבצים
  חיצוניים, מגבלות זמן / מעבד / זיכרון / גודל, משתמש בלי הרשאות), מגבלת האורך (`-t 15.5` ומדידה חוזרת),
  ניקוי קבצים זמניים (גם כשהתהליך נהרג), והחלופות (המרה בדפדפן, שירות מנוהל).
- `hero-transcode.sh` — העטיפה: בדיקת הקובץ במנתח של האפליקציה לפני ffmpeg → ffprobe מבודד → ffmpeg מבודד
  → בדיקת התוצאה → פרסום אטומי.
- `gate.ts` — ההחלטות, עם המנתח של האפליקציה (`src/engines/hospitality/media/video-info.ts`).
- `sweep.sh` — ניקוי תיקיות עבודה ותהליכים שנשארו אחרי קריסה.

ההמלצה בקצרה: תהליך רקע, סרטון אחד בכל פעם, בקונטיינר נפרד בלי רשת ובלי הרשאות; המקור בדלי פרטי עד
שההמרה מצליחה ונמחק אחריה. 18–47 שניות מעבד לסרטון של 15 שניות (1080p עד 4K HDR), 300–570MB זיכרון.
שני ממצאים מהמחקר כבר תוקנו באפליקציה: מדידת האורך של MP4 מקוטע (`tfdt`), והסרת מקום הצילום, דגם המכשיר
ותאריך הצילום מסרטונים שמועלים.
