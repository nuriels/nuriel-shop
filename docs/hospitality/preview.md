# תצוגה מקומית של Hospitality (P0)

עותק מקומי מלא של פלטפורמת Nuriel — אותן מיגרציות, אותה התחברות, אותו פאנל
פלטפורמה ואותו אזור ניהול — עם שלושה אתרי אירוח לדוגמה. בלי Staging, בלי שינוי
בשרת ובלי Production.

- **הכול מקומי:** מסד, אחסון קבצים, התחברות ושירותי מייל / תשלום מדומים — ב-Docker
  על המחשב שמריץ את הפקודה. שום נתון לא יוצא, ושום נתון אמיתי לא נכנס.
- **שמירה מובנית:** סקריפט נתוני ההדגמה עוצר מיד אם המסד או ה-API אינם מקומיים
  (`scripts/preview/local-guard.mjs`, ונבדק ב-`tests/unit/preview-guard.test.ts`).
- **מתג המנוע** (`HOSPITALITY_ENGINE=on`) נדלק רק בסקריפט המקומי
  (`e2e/scripts/app-up.sh`); בשרת הוא לא מוגדר — המנוע כבוי.

כל הנתונים נוצרים דרך המסלולים האמיתיים — הפונקציות של מנהל הפלטפורמה
(`admin_create_site`, `platform_set_flag`, `admin_set_subscription`) והפונקציות של
הבעלים (`update_settings`, `property_create`, `unit_create`, `whole_property_set`,
`team_add_manager`), עם הטוקן של המשתמש, כמו מהאפליקציה. החריג היחיד: שיוך הבעלים
לאתר נעשה ישירות במסד (כמו בבדיקות) — המסך לזה יגיע עם לשונית Hospitality בפאנל (P1).

## להתנסות במחשב שלך

דרישות: Docker פועל, Bun 1.4, Node 22, `psql` (בלקוח Postgres; ב-Mac:
`brew install libpq`), ודפדפן Chrome / Edge / Firefox (הם מפנים `*.localhost` למחשב
המקומי; Safari לא תמיד).

```bash
git checkout hospitality/stage-2
bun install
bun run hosp:preview          # מסד חדש + נתוני הדגמה + בנייה + הפעלה (כ-3–5 דקות)
```

בסוף ההפעלה מודפסות הכתובות והחשבונות. עצירה: Ctrl+C, ואז `bun run e2e:down`.

| פקודה | מה היא עושה |
|---|---|
| `bun run hosp:preview` | הכול מאפס: Supabase מקומי, נתוני הדגמה, בנייה והפעלה |
| `bun run hosp:preview --keep` | בלי לאפס את המסד — רק נתוני ההדגמה מחדש, בנייה והפעלה |
| `bun run hosp:demo` | רק נתוני ההדגמה מחדש (האתרים נמחקים ונוצרים שוב) |
| `bun run hosp:preview:record` | סיור מוקלט: צילומי מסך וסרטונים במחשב ובטלפון → `e2e/preview/out/index.html` |

## צילומי מסך וסרטונים

- `e2e/preview/walkthrough.spec.ts` עובר על התהליכים בממשק האמיתי — במחשב ובטלפון —
  ושומר צילום לכל שלב וסרטון לכל תהליך (MP4 כשיש ffmpeg). כל צעד גם נבדק, כך שהסיור
  הוא גם בדיקה של ערכת התצוגה.
- התהליכים: פאנל הפלטפורמה ← "היכנס לניהול" של אתר אירוח; בעלים של מתחם צימרים
  (לוח בקרה, יחידות, עריכת צימר, הגדרות, צוות); בעלים של וילה (עריכה); מנהלת קבלה
  במלון (רשימת חדרים, הוספת חדר, בלי מסכי בעלים); בעלים של המלון (הצוות); הקמה ראשונה
  באתר ריק ("מה אתם משכירים?"); והחנות — כמו קודם.
- 2c.3 (תהליכים 08–09): בעלים של מתחם הצימרים — עמוד המתחם, "השכרת המתחם כולו" עם
  בחירת היחידות (מוציאים את סוויטת הנוף), עמוד היחידה והשבתה שלה (היחידה עוברת ל"יחידות
  לא פעילות" ומקום בחבילה מתפנה); בעלים של המלון — סידור החדרים בחצים (ובמחשב גם
  בגרירה), נשמר מיד. אחרי ההקלטה נתוני ההדגמה נוצרים מחדש — כדי שתוכלו לנסות בעצמכם.
- ב-CI (כל דחיפה לענף `hospitality/**`): המשימה "Hospitality preview" מריצה את אותו
  סיור ומעלה את התוצרים כ-artifact בשם `hospitality-preview` (14 יום).

## ידוע בסביבה המקומית

- "היכנס לניהול" בפאנל הפלטפורמה פותח את כתובת האתר כמו בשרת אמיתי:
  `https://demo-zimmer.shop.localhost/admin-handoff#code=…`. מקומית האפליקציה על
  http ופורט 3100 — יש לשנות בשורת הכתובת ל-`http://` ולהוסיף `:3100` (ה-`#code` נשאר).
  הסיור המוקלט עושה זאת אוטומטית. האפליקציה עצמה לא משתנה.
- מיילים (קוד כניסה, התראות) לא נשלחים — הם נשמרים בשירות המדומה:
  `http://127.0.0.1:4010/__calls`. הכניסה בהדגמה — בסיסמה.
- בפאנל הפלטפורמה אתרי האירוח מופיעים בטבלת החנויות עם עמודות של חנות (מנוי
  "ניסיון", מוצרים / הזמנות) — המנוי של Hospitality ומגבלת היחידות יוצגו בלשונית
  Hospitality (P1).
- עדיין אין: אתר ציבורי, הזמנות, מחירים, תמונות (שלבים 2d–2k ושלב 4).

## מה אפשר לנסות (2c.3)
- ברשימת היחידות: לחיצה על שם יחידה פותחת את **עמוד היחידה** (פרטים, אורחים, חדרים, מצב
  היחידה, ולבעלים — מחיקה); "ניהול המתחם" פותח את **עמוד המתחם** (פרטים, היחידות שבו,
  "השכרת המתחם כולו", ולבעלים — ארכיון / החזרה / מחיקה).
- "סידור היחידות" — חצים או גרירה; כל הזזה נשמרת מיד.
- השבתה / הפעלה של יחידה; יחידה בתוך "כל המתחם" הפעיל לא מושבתת (יש הסבר במסך).
- שני דפדפנים על אותה יחידה — "עודכן בינתיים": הודעה ברורה, ושום שינוי לא נדרס.
- כמנהלת הקבלה במלון: הכול חוץ מארכיון ומחיקה (לא מוצגים, והשרת מסרב).

## מה יתווסף להדגמה בכל שלב
כל שלב מוסיף לשלושת אתרי ההדגמה נתונים **רק דרך הפונקציות האמיתיות** ופרק מוקלט (מחשב
וטלפון) — לפי הסדר שאושר: 2c.3 ← 2c.4 ← 2d ← 2e ← 2f ← 3a ← 2h ← 2i ← 3b ← 2j ← 2k.
הפירוט לכל שלב: `stage-2-plan.md` §2.6. מעקב הדרישות: `requirements-traceability.md`.
