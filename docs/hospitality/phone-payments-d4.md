# D4 — תשלום טלפוני (בלי סליקה באתר)

**ההחלטה (03/11/2026):** בשלב הזה אין סליקה באתר.
1. האורח שולח בקשת הזמנה באתר.
2. מיד אחרי השליחה הוא רואה: **"בקשת ההזמנה התקבלה. נציג העסק יצור איתך קשר טלפונית להשלמת
   התשלום ואישור ההזמנה"**.
3. בעל העסק רואה את פרטי ההזמנה ואת הטלפון של האורח באזור הניהול.
4. בעל העסק מתקשר וגובה במסוף האשראי שלו (מחוץ למערכת).
5. בעל העסק רושם את התשלום במערכת: סכום, אמצעי, תאריך והערה.
6. בקשה / הזמנה מאושרת / תשלום שהתקבל — מוצגים בנפרד.
7. "שולם" מופיע רק אחרי שהעסק רשם תשלום.
8. האורח רואה בבירור שאי אפשר לשלם באתר.

**על תשתית מיגרציה 23 בלבד:** יומן התשלומים, `payment_record`, `payment_void`. בלי מערכת
תשלומים נוספת, בלי ספק סליקה ובלי פרטי כרטיס.

מיגרציה: `20261103120000_hosp_phone_payments.sql` (M28) + rollback.

## מה נבנה

### לאורח (האתר)

- **לפני השליחה:**
  - בסיכום ההזמנה: "לא ניתן לשלם באתר: אחרי שליחת הבקשה, נציג העסק יתקשר אליכם להשלמת התשלום
    ואישור ההזמנה". אותו משפט חוזר מעל כפתור השליחה.
  - "שליחת הבקשה אינה מחייבת תשלום."
- **אחרי השליחה** (`/stay/booking-received`):
  - ההודעה המדויקת. בהזמנה מיידית: "ההזמנה התקבלה. נציג העסק יצור איתך קשר טלפונית להשלמת
    התשלום."
  - "לא ניתן לשלם באתר בשלב זה. העסק לא יבקש מכם פרטי כרטיס אשראי באתר או באימייל — רק בשיחה
    טלפונית איתו."
- **"ההזמנה שלי"** (הקישור המאובטח): שורת "תשלום" — "טרם שולם — נציג העסק יצור איתך קשר
  טלפונית" / "שולמה מקדמה" / "שולם". רק לפי מה שהעסק רשם.
- **מיילים:**
  - **"קיבלנו את בקשת ההזמנה":** אותה הודעה, ו"לא ניתן לשלם באתר, ולא נבקש ממך פרטי כרטיס
    אשראי באימייל".
  - **"ההזמנה אושרה":** "אם התשלום עוד לא הושלם — נציג העסק יצור איתך קשר טלפונית". לא
    נאמר "שולם".
- **בלי פרטי כרטיס בטופס:** טקסט בבקשות המיוחדות שנראה כמו מספר כרטיס (13–19 ספרות) נדחה,
  עם הסבר. הבדיקה בטופס ובשרת.

### לבעל העסק (אזור הניהול)

- **כרטיס "תשלום טלפוני" בעמוד ההזמנה:**
  - שלושת השלבים בנפרד, כל אחד עם סימון: 1. בקשת הזמנה, 2. הזמנה מאושרת, 3. תשלום נרשם.
  - כפתור **התקשרות לאורח** (המספר המלא — הצוות מורשה).
  - מה עושים: לגבות במסוף, לרשום ב"תשלומים" בלי מספר כרטיס, ולאשר.
  - הכרטיס מוצג עד שההזמנה גם אושרה וגם שולמה.
- **אישור הזמנה שלא נרשם לה תשלום:** חלון האישור אומר "עוד לא נרשם תשלום… ההזמנה תסומן כשולמה
  רק אחרי שתרשמו את התשלום". אפשר לאשר לפני התשלום ולגבות אחר כך.
- **רשימת ההזמנות:** תווית תשלום ליד כל הזמנה — "לא שולם" / "שולמה מקדמה" / "שולם". היא נפרדת
  מתווית מצב ההזמנה.
- **"תשלומים"** (הכרטיס הקיים):
  - "כרטיס אשראי (במסוף העסק)".
  - "התשלום נגבה בטלפון… כאן רק רושמים אותו, אחרי שהתקבל. אין סליקה באתר, ואין לרשום מספרי
    כרטיס".
  - הערה שנראית כמו מספר כרטיס חוסמת את הרישום, עם הסבר — בטופס, בשרת ובמסד.

### במסד (M28)

- **תיקון באג (מהשלב הקודם):**
  - **הבעיה:** `_payments_sync` עדכן את `amount_paid` אבל לא את `payment_status`. הזמנה שנרשם
    לה תשלום נשארה "לא שולם".
  - **התיקון:** עכשיו הסטטוס מחושב מהיומן — "לא שולם" / "שולמה מקדמה" / "שולם".
  - **נתונים קיימים:** הזמנות שבהן הסטטוס לא תאם את הסכום ששולם מתוקנות פעם אחת.
- **מערכת תשלומים אחת:** `confirm_payment` (Stage 1, לשרת בלבד, לא בשימוש) רשם סכום ישירות
  בהזמנה, מחוץ ליומן. עכשיו הוא רושם שורה ביומן (`provider = 'confirm'`). הסכום ששולם תמיד
  שווה ליומן — יש לכך בדיקה.
- **בלי מספרי כרטיס:** האילוץ `payments_note_no_card` דוחה הערה עם רצף של 13–19 ספרות.
