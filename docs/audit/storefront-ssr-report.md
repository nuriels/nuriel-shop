## 1. מה היה ומה תוקן

**לפני:** בעמוד הבית, בעמודי הקטגוריה, בעמודי המוצר ובעמודי המידע, ה-HTML שהשרת מחזיר הכיל בגוף **15 תווים בלבד**
("דלג לתוכן הראשי") — בלי H1, בלי מוצרים, בלי מחירים, בלי תמונות. הסיבה: `ssr: "data-only"` (בית, קטגוריה, מוצר,
עמודי תוכן) ו-`ssr: false` (אודות, צור קשר, תקנון, פרטיות, ביטול עסקה, מפת אתר).

**אחרי:** אותם עמודים נבנים בשרת עם מה שאורח רואה. בטעינה הראשונה השרת טוען — דרך הלקוח של השרת **שמוגבל לחנות של
הבקשה** — את הקטלוג של אורח (`get_catalog` בלי משתמש = המחירון הרגיל), את ההגדרות הציבוריות, הקטגוריות והבאנרים.
הרכיבים מתחילים מהנתונים האלה (זהים בשרת וברינדור הראשון בדפדפן — אין אי-התאמה בהידרציה), ואז הדפדפן ממשיך **בדיוק
כמו קודם**: טוען שוב לפי מי שמחובר (דרג מחיר / מחירון אישי), מלאי עדכני, עגלה.

## 4. ביצועים (מדידה מקומית, 152 מוצרים; טלפון מדומה: Pixel 7, מעבד ×4 איטי, רשת 1.6Mbps / 150ms)

| עמוד    | LCP לפני | LCP אחרי | CLS לפני | CLS אחרי  |
| ------- | -------- | -------- | -------- | --------- |
| בית     | 12.5s    | **5.5s** | 0.70     | **0.002** |
| קטגוריה | 16.2s    | **5.7s** | 0.34     | **0.002** |
| מוצר    | 15.0s    | **4.8s** | 0.07     | **0.005** |
| אודות   | 10.9s    | **4.6s** | 0.03     | **0**     |

- **זמן שרת** (חציון, 152 מוצרים): בית 21→35ms, קטגוריה 16→32ms, מוצר 51→69ms.
- **גודל HTML**: בית 15KB→215KB (gzip: 4KB→**20KB**), מוצר 16KB→77KB (gzip: 13KB). בייצור nginx כבר מכווץ HTML (gzip).
- **FCP** בבית / קטגוריה עלה מעט (4.6s→5.5s) בגלל HTML גדול יותר ברשת איטית בלי gzip מקומי — בייצור עם gzip הפער קטן יותר.
- **עומס על המסד:** לאורח — כמו קודם (קריאה אחת מהדפדפן) + בשרת קריאה אחת לדקה לכל חנות (מטמון), והגדרות / קטגוריות
  בכל טעינה ראשונה של עמוד.

## 7. ממצאים שלא טופלו (מחוץ לשלב 1 — לאישור בנפרד)

1. **כרטיסי המוצר בקטגוריות הם כפתורים (חלון תצוגה מהירה), לא קישורים** — גוגל לא מקבל קישור `<a href>` מהקטגוריה
   לעמוד המוצר (מוצרים מתגלים רק דרך מפת האתר). תיקון: קישור אמיתי שהלחיצה עליו עדיין פותחת את החלון — שינוי UI קטן.
2. **מפת האתר (`/sitemap`) — באג קיים:** שאילתה בדפדפן נכשלת (400, `column record.id does not exist`), והעמוד מציג את כל
   הקטגוריות במקום רק את הפעילות.
3. לקוח מחובר עם מחירון משלו רואה לשנייה את המחיר של אורח (מה-HTML) עד שהמחיר שלו נטען (הוספה לסל חסומה באותו זמן).
4. מוצר שלא קיים — עדיין 200 + noindex (soft 404), כמו קודם.
5. במצב תחזוקה, תגיות ה-head של עמוד מוצר (כותרת / JSON-LD) נשלחות — כמו קודם.

## 8. תוכנית פריסה (רק אחרי אישור שלך)

**סוג השינוי:** קוד בלבד — אין מיגרציה, אין שינוי במסד או ב-nginx. Rollback = החזרת ה-image הקודם.

1. **אישור** — שלך, על הענף `claude/store-ssr-seo` (commit אחרון בדוח).
2. **מיזוג לענף השחרור** (לפי הנוהל: `release/next` / הענף שממנו השרת בונה) — רק באישור. לפני כן: CI ירוק על ה-commit
   הממוזג. שים לב: ענפים אחרים שממתינים (Hospitality SEO, audit) לא נכללים — הם נפרדים.
3. **גיבוי** — לא נדרש למסד (אין שינוי), אבל לפי הנוהל: תיוג ה-image הנוכחי (`docker tag … :pre-ssr`) כדי שהחזרה תהיה מיידית.
4. **בנייה והפעלה** — `docker compose build && docker compose up -d` (או `release-next.sh --deploy <commit>`, שמחזיר
   אוטומטית לגרסה הקודמת אם בדיקת התקינות נכשלת).
5. **בדיקות עשן מיד אחרי (קריאה בלבד):**
   - `curl -A Googlebot https://nuriel-shop.nuri1.fit/` → H1, שמות מוצרים ומחירים בגוף (לא 15 תווים).
   - עמוד מוצר + קטגוריה + אודות → H1 ותוכן.
   - חנות נוספת בפלטפורמה → רק המוצרים שלה.
   - `nuriel-app2.nuri1.fit` → דף הנחיתה כמו קודם.
   - בדפדפן: הוספה לסל, קופה, התחברות לקוח — בלי שגיאות בקונסול.
   - לוגים: `docker logs --since 5m <app>` — בלי `[storefront-seed]` שגיאות.
6. **Rollback** אם משהו לא תקין: `docker tag …:pre-ssr` חזרה + `docker compose up -d` (דקה; אין מה להחזיר במסד).
7. **אחרי הפריסה (שלך, ב-Search Console):** "בדיקת כתובת URL" לעמוד הבית ולעמוד מוצר → "בדיקת כתובת אתר פעילה" →
   "צילום מסך" / HTML — לוודא שהתוכן מופיע; ובקשת הוספה לאינדקס לכמה עמודים מרכזיים. מעקב 2–4 שבועות ב-Pages / Performance.
