# אבחון SEO — Nuriel Shop ו-NURIEL APP2 (חלק 1 + חלק 5)

> **קריאה בלבד.** לא שונה קוד, לא שונה אתר חי, לא בוצעה פריסה, לא נגעתי בחשבון Google / Search Console.
> כל הבדיקות: בקשות HTTP ציבוריות (גם ב-User-Agent של Googlebot) וקריאת הקוד בענף. תאריך: 2026-11-17.
> המדידות של מהירות — מעבדה (Chromium, אמולציית Pixel 7, דרך ה-proxy של סביבת הענן), **לא** נתוני משתמשים אמיתיים.

## 0. השורה התחתונה

1. **הבעיה העיקרית בחנות הפלטפורמה איננה מילות מפתח — היא שגוגל מקבל עמוד ריק.** בעמוד הבית, בעמודי הקטגוריה
   ובכל 145 עמודי המוצר, ה-HTML שמגיע מהשרת מכיל בגוף רק "דלג לתוכן הראשי" (15 תווים): אין H1, אין שם מוצר, אין
   מחיר, אין תיאור, אין תמונות. התגיות (כותרת, תיאור, קנונית, JSON-LD, OG) כן נוצרות בשרת. גוגל יכול להריץ JS,
   אבל זה בתור נפרד ואיטי, ותוכן שמופיע רק אחרי JS מאונדקס פחות ולאט יותר — בדיוק התסמין של "לא מופיע בגוגל".
2. **שתי חנויות חיות לאותו עסק מתחרות זו בזו:** `https://nuriel-shop.co.il` (מערכת חנות אחרת, לא בקוד הזה, 148
   מוצרים בכתובות עבריות) ו-`https://nuriel-shop.nuri1.fit` (הפלטפורמה, 145 מוצרים). כל אחת קנונית לעצמה. **לא
   ניחשתי איזו הראשית — זו החלטה שלך.**
3. **סתירה במיקום העסק:** co.il אומר "חנות מחשבים **ברחובות**"; nuri1.fit אומר "**בבית שמש**". צריך לקבוע אחד
   לפני כל עבודת SEO מקומי.
4. **NURIEL APP2 בנוי נכון טכנית** (SSR מלא, H1, 7×H2, Schema) — אבל זה עמוד אחד: מפת האתר מכילה כתובת אחת.
5. **Search Console — אין לי גישה מורשית** לאף אחד מהדומיינים (אין חיבור Google בסביבה). לא נבדק, לא שונה.

## 1. כתובת החנות — מהקוד ומהקונפיגורציה (לא ניחוש)

| מקור                                      | ערך                                                                              |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| `deploy/nginx/nuriel-shop.nuri1.fit.conf` | `server_name nuriel-shop.nuri1.fit nuriel.nuri1.fit`                             |
| `deploy/setup-selfhost.sh`                | `SITE_URL=https://nuriel-shop.nuri1.fit`, `PLATFORM_ADMIN_HOST=nuriel.nuri1.fit` |
| `src/platform/branding/credit.ts`         | `NURIEL_CREDIT_URL = "https://nuriel-app2.nuri1.fit"` (קרדיט בכל האתרים)         |
| `src/components/AppFooter.tsx:125`        | "מופעל ע״י נוריאל מחשבים" → `https://nuriel-shop.co.il`                          |

**מסקנה:** חנות הפלטפורמה = `https://nuriel-shop.nuri1.fit`. `nuriel.nuri1.fit` → 307 ל-`/platform` (ניהול).
`nuriel-shop.co.il` איננו בקוד הזה (שרת `customNoobServer`, PHPSESSID, `catalog/view`, Yoast) — אבל כל חנות בפלטפורמה
מקשרת אליו מהפוטר. הערה: מסמך `stage-1-plan.md` אומר שהקרדיט של Hospitality עבר ל-`m.nuri1.fit`; בקוד הנוכחי
הוא `nuriel-app2.nuri1.fit` (המסמך לא מעודכן). `m.nuri1.fit` הוא מוצר אחר ("Moments"), בלי robots ובלי sitemap (404).

## 2. סטטוס הדומיינים

| כתובת                             | תוצאה                                                                             |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `https://nuriel-shop.nuri1.fit/`  | 200, HSTS, בלי `X-Robots-Tag`                                                     |
| `https://nuriel-app2.nuri1.fit/`  | 200, HSTS, `robots: index, follow`                                                |
| `https://nuriel-shop.co.il/`      | 200                                                                               |

| `https://nuriel-shop.co.il/xyz`   | **301 → `http://`**`nuriel-shop.co.il/xyz/` (הפניה ל-HTTP ואז 404) — שרשרת מיותרת |

| מוצר שלא קיים (`/product/<uuid>`) | **200** + `noindex` + "המוצר לא נמצא" — soft 404; עדיף סטטוס 404                  |

## 3. חנות הפלטפורמה — `nuriel-shop.nuri1.fit`

### 3.1 מה Googlebot מקבל ב-HTML (בלי JS)

| עמוד                       | טקסט בגוף |  H1 |  H2 | תמונות | כותרת / תיאור / קנונית / JSON-LD                  |
| -------------------------- | --------: | --: | --: | -----: | ------------------------------------------------- |
| בית                        |        15 |   0 |   0 |      0 | ✓ (WebSite + עסק), כותרת רק "נוריאל מחשבים"       |
| מוצר                       |        15 |   0 |   0 |      0 | ✓ Product / Offer / BreadcrumbList / Organization |
| אודות, צור קשר, תקנון וכו' |        ~0 |   0 |   0 |      0 | כותרת בלבד (`ssr: false` — אפילו ה-loader לא רץ)  |
| **השוואה: APP2**           |     8,758 |   1 |   7 |     11 | ✓                                                 |

אחרי JS (בדפדפן) אותו עמוד בית מכיל 15,249 תווים ו-H1 אחד — כלומר התוכן קיים, רק לא בשרת.

### 3.2 הסיבה בקוד

| קובץ                                                               | הגדרה                                                          | מאז                                                 |
| ------------------------------------------------------------------ | -------------------------------------------------------------- | --------------------------------------------------- |
| `src/routes/index.tsx:95`                                          | `ssr: isPortalSite() ? true : "data-only"`                     | `c109c15` 2026-10-05 (חלק 21; לפני כן `ssr: false`) |
| `src/routes/product.$productId.tsx:84`                             | `ssr: "data-only"` — "התוכן עצמו (מחיר לפי מי שמחובר…) בדפדפן" | חלק 14/21                                           |
| `src/routes/pages.$slug.tsx:24`                                    | `ssr: "data-only"`                                             |                                                     |
| `about`, `contact`, `terms`, `privacy`, `cancellations`, `sitemap` | `ssr: false`                                                   | `06a3900` 2026-10-05                                |

`data-only` = ה-loader וה-head רצים בשרת, הקומפוננטה רק בדפדפן. הסיבה המתועדת: מחיר לפי הלקוח המחובר ומניעת
אי-התאמה בהידרציה. כלומר **מאז שהחנות קיימת (2026-10-02) גוף העמודים מעולם לא נשלח מהשרת**. ב-APP2 ה-SSR המלא
נוסף ב-`ad3a2fe` — וזה העמוד היחיד שעובד.

שאר ה-routes עם `ssr: false` (admin, account, checkout, login, register, platform…) — פרטיים, ושם זה בסדר.

### 3.3 שאר הבדיקות

| נושא                    | ממצא                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| robots.txt              | תקין: חוסם admin, account, checkout, login, register, `/_serverFn/`, `/api/`, `?q=`. מפנה ל-sitemap ✓        |
| sitemap.xml             | 182 כתובות: 145 מוצרים (עם תמונה ו-lastmod), 27 קטגוריות, 7 עמודים קבועים + עמודי תוכן ✓                     |
| כתובות                  | מוצרים — `/product/<uuid>` (בלי מילים); קטגוריות — `/?category=<שם>` (פרמטר על דף הבית)                      |
| כותרת הבית              | "נוריאל מחשבים" בלבד — בלי מילה על מה העסק מוכר                                                              |
| OG / Twitter            | ✓ כותרת, תיאור, תמונה, `he_IL`                                                                               |
| אימות גוגל              | תגית `google-site-verification` קיימת (מישהו כבר אימת את הדומיין ב-Search Console)                           |
| עמודים פרטיים           | `/login`, `/admin` — 200 בלי `noindex`, אבל חסומים ב-robots ✓. אין אינדוקס של מסכי ניהול כרגע                |
| גישה בלי התחברות        | הקטלוג והמוצרים פתוחים ✓ (מחיר לאורח)                                                                        |
| מובייל                  | בלי גלילה אופקית ✓                                                                                           |
| מהירות (מעבדה, Pixel 7) | בית: TTFB 1.0s, **LCP ≈ 10s, CLS 0.81** (גרוע מאוד), 175 בקשות, ~4.5MB. מוצר: **LCP ≈ 8s**, CLS 0.07, ~2.8MB |

ה-CLS הגבוה וה-LCP האיטי באים מאותה סיבה: הדף מגיע ריק, ואז הקטלוג "קופץ" פנימה אחרי JS ונתונים.

## 5. `nuriel-shop.co.il` (לא בקוד הזה — לידיעה בלבד)

כותרת "נוריאל מחשבים – מחשבים, ציוד היקפי ותוכנות | משלוחים בכל הארץ", תיאור "ברחובות", קנונית לעצמו, **אין
H1**, אין JSON-LD, 8 מתוך 31 תמונות בלי alt, 148 מוצרים בכתובות עבריות, LCP ≈ 2.3s. מכיוון ששתי החנויות מוכרות
כנראה את אותו קטלוג, גוגל רואה תוכן כפול בשני דומיינים, וכל אחד מהם טוען שהוא המקור.

## 6. Search Console (חלק 5)

אין בסביבה הזו גישה מורשית לחשבון Google / Search Console של אף דומיין (אין חיבור, אין מפתח). **לא בוצעה שום
פעולה בחשבון.** כדי לבדוק אינדוקס, Pages, Excluded, Crawled/Discovered – not indexed, Sitemaps, Manual Actions,
Security Issues ו-Performance (כולל השוואה היסטורית) צריך אחד מאלה:

- ייצוא מ-Search Console (Pages + Performance, 16 חודשים) שתעלה לכאן; או
- גישת קריאה בלבד (משתמש "Restricted") לחשבון שירות — רק באישור מפורש שלך.
